# Implementation Plan – Mini-Lab 3 Satisfaction Kiosk

Generated by Claude (Anthropic) from Prompts 2 and 3 and the revised class and state diagrams. Author of the design: Emanuel Petrini.

## Files

| File | Classes | Role |
|---|---|---|
| `FeedbackStats.py` | `FeedbackStats` | Model: vote counts, satisfaction %, low-score check, reset |
| `ProximitySensor.py` | `ProximitySensor(UltrasonicSensor)` | Customer detection; ignores failed (-1) readings |
| `KioskView.py` | `KioskView` | View: every LCD, light-strip, and buzzer output |
| `KioskController.py` | `KioskController` | Controller and `StateModel` handler |
| `main.py` | – | Creates `KioskController` and calls `run()` |

No PicoLibrary file is modified. Library files used: `StateModel.py`, `Counters.py` (`SoftwareTimer`), `Button.py`, `Sensors.py`, `Sensors_advanced.py` (`UltrasonicSensor`), `Displays.py` (`LCDDisplay`), `LightStrip.py`, `Lights.py`, `Buzzer.py` (`PassiveBuzzer`), `Log.py`, plus the LCD helpers.

## Hardware

LCD SDA GP0 / SCL GP1 · light strip DIN GP2 · HC-SR04 TRIG GP3 / ECHO GP4 · buzzer GP16 · buttons red GP17, green GP18, manager GP19 (active-low, internal pull-up).

## StateModel setup

1. `StateModel(5, self, debug=True)`.
2. Register inputs first, which creates their events: buttons `red`, `green`, `manager` (`*_press`, `*_release`), sensor `proximity` (`proximity_trip`, `proximity_untrip`), timer `timer` (`timer_timeout`).
3. Transition table:

| From | Events | To |
|---|---|---|
| IDLE (0) | `proximity_trip` | PROMPT (1) |
| IDLE (0) | `manager_press` | MANAGER (4) |
| PROMPT (1) | `green_press`, `red_press` | THANKS (2) |
| PROMPT (1) | `timer_timeout` | IDLE (0) |
| ALARM (3) | `manager_press` | MANAGER (4) |
| MANAGER (4) | `green_press`, `manager_press`, `timer_timeout` | IDLE (0) |

THANKS has no table transition; its timeout is handled by the choice below.

## UML features StateModel doesn't support, and how they're implemented

- **Transition actions on PROMPT's arrows** (`/ _stats.record(True|False)`): in `stateLeft(PROMPT, event)`. `gotoState()` calls `stateLeft` before `stateEntered`, so THANKS shows the updated percentage.
- **Choice after THANKS** (`[is_low] → ALARM`, `[else] → IDLE`): `processEvent` finds no transition for `timer_timeout` in THANKS and calls `stateEvent`, which calls `_model.gotoState(ALARM or IDLE, event)`.
- **MANAGER internal transition on `red_press`**: in `stateEvent(MANAGER, "red_press")`: reset stats, `show_reset()`, restart the 10 s timer, stay in MANAGER.

## Entry, exit, and do actions

| State | Entry | Exit | Do |
|---|---|---|---|
| IDLE | `show_idle(pct, total)` (gauge) | – | – |
| PROMPT | `show_prompt()`, timer 8 s | (record vote), cancel timer | – |
| THANKS | `show_thanks(...)` + beep, timer 3 s | cancel timer | – |
| ALARM | `show_alarm(pct)` | `silence()` | `siren_step()` every loop |
| MANAGER | `show_manager_menu(pct, total)`, timer 10 s | cancel timer | – |

## Edge cases covered

- Extra presses in THANKS, IDLE, or ALARM have no transition and are ignored (no double votes, no voting during the alarm).
- `proximity_trip` only fires when the sensor changes from clear to blocked, so a customer must step away before voting again.
- No votes: `satisfaction_pct()` returns 100, the LCD says "No votes yet", and the strip glows dim blue.
- The alarm needs at least 5 votes (`MIN_VOTES`) below 30% (`LOW_PCT`).
- `ProximitySensor.tripped()` ignores the -1 that `UltrasonicSensor.distance()` returns on a failed reading.

## Testing

Before loading on the Pico, the state machine was run on a desktop with stand-ins for the Pico hardware modules. Results: idle shows "No votes yet" with a blue gauge; a green vote shows "Thanks! :)" and 100%; extra presses during THANKS are ignored; an abandoned prompt returns to idle; 1 green + 4 red votes (20%, 5 votes) raises ALARM; green during the alarm is ignored; the manager button silences it; red resets the stats; green returns to an empty idle; the sensor reports tripped at 6.2 cm, not at 25 cm, and not on a -1 reading.
